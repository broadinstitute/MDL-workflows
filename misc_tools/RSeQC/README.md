# RSeQC gene body coverage

Terra-launchable WDL for RSeQC `geneBody_coverage.py`.

## Workflow

`GeneBodyCoverage.wdl` runs gene body coverage for one sorted, indexed BAM using:

```text
quay.io/biocontainers/rseqc:5.0.4--pyhdfd78af_1
```

That BioContainers image includes RSeQC 5.0.4 and R, so no local Dockerfile is needed for this workflow.

## Inputs

- `sample_id`: sample name and output filename prefix. Use only letters, numbers, `.`, `_`, and `-`.
- `bam`: sorted BAM file.
- `bai`: BAM index. RSeQC requires indexed BAMs, and the selected RSeQC container does not include `samtools`, so the index is a required input.
- `refgene_bed`: 12-column BED gene model. For human workflows this is commonly a UCSC refGene-style BED12 or an RSeQC-compatible BED12 converted from GTF/GFF.
- `min_mrna_length`: minimum transcript length. RSeQC requires this to be at least `100`.
- `output_format`: `pdf`, `png`, or `jpeg`.

## Outputs

- `coverage_table`: coverage values over the 100 gene-body percentiles.
- `curves_plot`: normalized gene-body coverage curve plot.
- `r_script`: R script generated by RSeQC.
- `stdout_log`, `stderr_log`, `rseqc_log`: run logs.
- `multiqc_files_tar_gz`: compact tarball containing `*.geneBodyCoverage.txt`, which is the file parsed by MultiQC's RSeQC gene-body coverage module.
- `output_tar_gz`: bundle of the main outputs.

## Terra notes

For a sample launch, map inputs from a sample table, for example:

```text
this.sample_id
this.bam
this.bai
```

All captured report filenames are prefixed with `sample_id`, such as `sample_1.geneBodyCoverage.txt` and `sample_1.geneBodyCoverage.curves.pdf`.

For cohort-level MultiQC, collect and unpack the per-sample `multiqc_files_tar_gz` files into one directory, then run MultiQC on that directory. The important file for this module is `*.geneBodyCoverage.txt`.
