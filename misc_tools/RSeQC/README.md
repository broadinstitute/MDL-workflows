# RSeQC gene body coverage

Terra-launchable WDL for RSeQC `geneBody_coverage.py`.

## Workflow

`GeneBodyCoverage.wdl` runs gene body coverage for one or more sorted, indexed BAMs using:

```text
quay.io/biocontainers/rseqc:5.0.4--pyhdfd78af_1
```

That BioContainers image includes RSeQC 5.0.4 and R, so no local Dockerfile is needed for this workflow.

## Inputs

- `analysis_id`: output prefix.
- `sample_ids`: sample names, same order as `bams` and `bais`.
- `bams`: sorted BAM files.
- `bais`: BAM indices. RSeQC requires indexed BAMs, and the selected RSeQC container does not include `samtools`, so indices are required inputs.
- `refgene_bed`: 12-column BED gene model. For human workflows this is commonly a UCSC refGene-style BED12 or an RSeQC-compatible BED12 converted from GTF/GFF.
- `min_mrna_length`: minimum transcript length. RSeQC requires this to be at least `100`.
- `output_format`: `pdf`, `png`, or `jpeg`.

## Outputs

- `coverage_table`: coverage values over the 100 gene-body percentiles.
- `curves_plot`: normalized gene-body coverage curve plot.
- `heatmap_plots`: heatmap plot when at least 3 BAMs are provided; empty array otherwise.
- `r_script`: R script generated by RSeQC.
- `sample_manifest`: mapping from requested sample IDs to staged BAM names used by RSeQC.
- `stdout_log`, `stderr_log`, `rseqc_log`: run logs.
- `output_tar_gz`: bundle of the main outputs.

## Terra notes

For a sample-set launch, map `sample_ids`, `bams`, and `bais` to arrays from the set membership table, for example:

```text
this.samples.sample_id
this.samples.bam
this.samples.bai
```

For a single-sample launch, pass one-element arrays:

```text
[this.sample_id]
[this.bam]
[this.bai]
```
